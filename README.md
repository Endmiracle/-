# 羽衣电竞 · 陪玩制度问答系统

面向**羽衣电竞陪玩俱乐部**的陪玩师制度问答系统：微信小程序客户端 + 零依赖 Node RAG 引擎。
陪玩师用口语提问（「炸单扣多少钱」「钻石保级要几单」），系统从俱乐部制度文档里检索对应条款，
由大模型组织成带引用来源的答案。

不依赖 RAGFlow 或任何第三方 RAG 服务：文档入库、解析切片、检索排序、提示词组装、流式生成、引用溯源全部自己实现。
但**对外接口形态与 RAGFlow 官方 SDK 保持一致**（`/api/v1/chats/{id}/completions`、`Bearer` 鉴权、`reference.chunks` 结构），
所以设置页里把地址指向真实 RAGFlow 也能直接跑通 —— 一份客户端，两条后端路线。

内置知识库（已随项目提供，可直接导入）：
- 《羽衣电竞-陪玩师制度统一化》—— 炸单规则与价格、队内沟通、订单报备、打手规范、物资要求、罚款制度、服务态度
- 《基本制度》—— 陪玩师等级与分成（新晋打手 65% / 钻石 70% / 魔王 75% / 明星 80%）、好评要求、客服与投诉链接

```
┌─────────────────────┐        ┌──────────────────────────────────────┐        ┌──────────────┐
│  微信小程序（原生）  │  SSE   │      RAG 引擎（Node，零依赖）         │  HTTPS │  大模型 API  │
│  问答 / 知识库 /     │ ─────► │  入库切片 → BM25+向量检索 → 提示词    │ ─────► │ DeepSeek 等  │
│  助手 / 会话 / 设置  │ ◄───── │  → 流式生成 → 引用溯源 → 会话落库     │        │ OpenAI 兼容  │
└─────────────────────┘        └──────────────────────────────────────┘        └──────────────┘
```

## 一、5 分钟跑通

### 第 1 步：启动引擎

需要 Node 16 以上（无需 `npm install`，引擎只用内置模块）。

```bash
cd yuyi-esports-qa
npm run proxy
# 等价于 node server/index.js
```

启动后会打印可用地址：

```

    本机模拟器   http://127.0.0.1:8787
```

浏览器打开任意一个地址，能看到状态页（知识库/文档/切片/助手/会话数量）。

## 二、联调：三种场景怎么填地址

小程序对网络有硬限制（**必须 HTTPS + 域名白名单**），所以「填哪个地址」取决于你在哪跑：

| 场景 | 服务地址怎么填 | 还需要做什么 |
|---|---|---|
| **开发者工具模拟器** | `http://127.0.0.1:8787` | 详情 → 本地设置 → 勾选「不校验合法域名」 |
| **真机调试**（手机扫码调试） | `http://电脑局域网IP:8787` | 手机与电脑同一 WiFi；点「真机调试」而不是「预览」 |
| **正式上线 / 日常真机使用** | `https://你的域名` | 引擎部署到服务器，配 HTTPS 证书，域名完成 ICP 备案并在小程序后台加白名单 |

**为什么手机不能用 127.0.0.1**：手机上的 127.0.0.1 指向手机自己，引擎在电脑上。**为什么「预览」不行**：预览走正式环境校验，HTTP 和 IP 都会被拦；「真机调试」会跳过域名校验。

**上线最省事的做法**：引擎跑在能访问知识库的机器上 → 用内网穿透（frp / cpolar 等）或直接部署到有公网域名的服务器 → 配证书后把域名填进设置页。引擎已支持 HTTPS：配置 `.env` 里的 `SSL_KEY_PATH` / `SSL_CERT_PATH` 后重启即自动切换为 https。

## 五、RAG 链路是怎么实现的

### 1. 入库：抽取 → 切片

| 格式 | 处理方式 |
|---|---|
| txt / md / csv / json / log / yml | 直接读取 |
| html | 行内标签剔除（`赛制<b>规则</b>` → `赛制规则`）、块级标签转段落 |
| **docx** | 用 Node 内置 `zlib` **手写 zip 解析**（EOCD → 中央目录 → inflateRaw），从 `word/document.xml` 提取正文，零依赖 |
| **pdf** | 尽力而为：解压内容流 + 提取 `Tj`/`TJ` 文本；抽出 CID 乱码时**主动报错**而不是把垃圾灌进知识库 |
| 其他 | 明确提示不支持（含「.doc 请另存为 .docx」） |

切片策略：按 **标题 → 段落** 结构化切分，超长段落再按 `。`/`；` 边界硬切并保留重叠；过短的尾块向前合并。标题作为元数据保留，并在检索索引里拼进文本（标题往往是高信息量主题词，但展示时只显示正文）。

**表格单独成块**（针对本材料的关键优化）：制度里的罚款金额、炸单价格、客服链接大量以 Markdown 表格承载。表格与正文混切会把「5 元 / 局 / 人」和它对应的项目名拆开，检索精确度明显下降。所以表格识别为独立块，**每个切片都重复携带表头**（单独看也知道这个金额对应哪个项目），并且不参与「短块合并」，也不会和正文黏在一起。

### 2. 检索：BM25（+ 可选向量）

- **分词**：中文按连续汉字段切 **2-gram**（`赛制规则` → 赛制/制规/规则），英文数字按词切。无词典方案里效果最稳，且不引入 jieba 之类的依赖。
- **打分**：标准 BM25（k1=1.5，b=0.75），IDF 带 +1 平滑避免负分。
- **过滤**：用**概念覆盖率**（命中的概念数 / 查询概念总数）做绝对阈值。

> 这里有个刻意的设计：**排序用 BM25 原始分（相对量纲），过滤用覆盖率（绝对量纲）**。很多人把 BM25 分数当「相似度阈值」，但 BM25 没有绝对量纲，同一阈值在不同语料上含义完全不同 —— 这是自建 RAG 语义失控最常见的原因。

- **混合检索（可选）**：配置 `EMBEDDING_MODEL` 后自动启用，`similarity = α × 覆盖率 + (1-α) × 余弦`，两项都是 0~1 的绝对量，此时阈值语义与 RAGFlow 的 `similarity_threshold` 一致。向量接口失败会**自动降级**为纯 BM25 并在界面上标明。

### 2.5 针对陪玩师提问习惯的三处加固

制度原文是书面语，陪玩师提问是口语，字面匹配会直接漏召回。做了三件事（均由 `npm run eval` 回归保护）：

| 问题 | 做法 |
|---|---|
| 问「扣钱」而原文写「罚款」 | **同义词概念归并**（`server/rag/synonyms.js`，19 组）。查询命中组内任一词即算命中该概念；同组内多个词命中同一片段只取最高分，避免重复计分虚高 |
| 问「等级」而原文写「级别」 | 同上，已内置 `等级/级别/段位`、`升级/晋升`、`保级/掉级`、`陪玩师/打手`、`老板/客户` 等 |
| 问句里的虚词拉低覆盖率 | **查询侧噪音过滤**：含「的/了/是/在…」的二字组合与「哪些/怎么/请问…」在查询侧剔除（索引侧不动）。它们命中率本就为 0，却会拉低真实命中的覆盖率 |
| 文档头「> 来源文档/版本/适用范围」频繁挤进前 3 | **元信息切片降权**：整段都是引用块/来源说明的切片标记 `isMeta`，排序分 ×0.25（内容不丢，只是不再抢占前排） |

新增同义词：改 `server/rag/synonyms.js` 的 `GROUPS` 即可，无需改其它代码；改完跑 `npm run eval` 验证效果。

### 3. 生成：提示词 + 引用

系统提示词内置三条硬约束：只能依据知识片段回答、检索不到就明说缺少什么、引用时标 `[1] [2]`。上下文按相关度从高到低填充，超出预算自动截断。

`reference` 结构与 RAGFlow 完全一致（`chunks[].content_with_weight` / `document_name` / `similarity` / `doc_aggs`），额外补了 `heading`（章节）与 `coverage`/`bm25`/`cosine` 三个诊断字段，方便在小程序里核对召回质量。

### 4. 流式：为什么必须自己写 UTF-8 解码

小程序**没有全局 `TextDecoder`**，而常见写法 `String.fromCharCode.apply(null, new Uint8Array(buf))` 在中文场景下必然乱码：一个汉字占 3 字节，网络分片经常把它从中间切开，半个字符被独立解码就成了乱码。

所以 `utils/stream.js` 实现了一个**带状态**的增量解码器：遇到不完整的字节序列就留在 `pending` 里等下一个分片，并能在遇到非法字节时重新同步。测试里对每个样例字符串**遍历全部切分点**（含逐字节喂入）验证解码结果与原串完全一致。

另外 RAGFlow 的 `answer` 是**累积全文**（不同版本也可能是增量片段），所以用「新文本是否以旧文本开头」来判断并兼容两种语义，避免整段答案被重复叠加。

## 六、API 一览

路径与 RAGFlow 官方 SDK 对齐，`/api/v1` 前缀，`Authorization: Bearer` 或 `X-Access-Token` 鉴权（服务端设了 `ACCESS_TOKEN` 才校验）。成功返回 `{ code: 0, data }`，业务失败返回 HTTP 200 + `{ code: 非0, message }`。

```
GET    /health                                   健康检查与统计

GET    /api/v1/datasets                          知识库列表（含文档/切片统计）
POST   /api/v1/datasets                          创建知识库
GET    /api/v1/datasets/{id}                     知识库详情
PUT    /api/v1/datasets/{id}                     更新
DELETE /api/v1/datasets/{id}                     删除（级联）

GET    /api/v1/datasets/{id}/documents           文档列表（含解析状态与进度）
POST   /api/v1/datasets/{id}/documents           新增文档（JSON 文本 或 multipart 文件）
GET    /api/v1/datasets/{id}/documents/{docId}   文档详情
DELETE /api/v1/datasets/{id}/documents/{docId}   删除文档（级联切片）
POST   /api/v1/datasets/{id}/documents/{docId}/reparse      重新解析
GET    /api/v1/datasets/{id}/documents/{docId}/chunks       某文档的切片
GET    /api/v1/datasets/{id}/chunks              全部切片（分页/关键词）
POST   /api/v1/retrieval                         检索测试（不经过大模型）

GET    /api/v1/chats                             助手列表 / POST 创建
GET    /api/v1/chats/{id}                        助手详情 / PUT 更新 / DELETE 删除
GET    /api/v1/chats/{id}/sessions               会话列表 / POST 创建 / DELETE 删除
POST   /api/v1/chats/{id}/completions            问答（stream 默认 true，SSE；false 则返回 JSON）
```

**解析是异步的**：`POST documents` 立即返回 `status: "parsing"`，小程序轮询列表刷新进度，因此大文件不会撑爆上传超时。

**解析失败是可见的**：失败文档保留在列表里并展示具体原因（如「PDF 可能是扫描件，请先 OCR」），可一键重试，而不是静默丢失。

## 八、排障速查

| 现象 | 原因与处理 |
|---|---|
| 小程序报「域名未通过校验」 | 开发者工具勾选「不校验合法域名」；真机用「真机调试」；上线需 HTTPS + 备案域名 |
| 自检第 1 项就失败 | 地址格式不对（要以 `http://` 或 `https://` 开头）或引擎没启动 |
| 自检卡在「拉取助手列表」 | 访问令牌与服务端 `ACCESS_TOKEN` 不一致；或引擎监听在 `127.0.0.1`，手机访问不到（用 `HOST=0.0.0.0`） |
| 上传成功但文档解析失败 | 看文档卡片上的红色原因：PDF 扫描件需先 OCR；`.doc` 需另存 `.docx`；内容过短 |
| 问答回答「知识库中没有找到相关内容」 | 检索没命中：到知识库详情页用「检索测试」查召回；把助手阈值调低、Top-K 调大；确认文档已「已解析」状态 |
| 回答是「检索结果原文片段」 | 服务端没配 `LLM_API_KEY`，属于降级模式，配上即恢复自然语言回答 |
| 回答中途截断并提示中断 | 大模型侧超时/限流。调大 `LLM_TIMEOUT_MS`，或调小助手「最大输出长度」 |
| 界面提示「向量不可用」 | 向量接口调用失败，已自动降级为 BM25；检查 `EMBEDDING_*` 配置 |
| 回答显示成方块/乱码 | 理论上不会出现（已有逐字节解码测试）；若真遇到请反馈具体机型与基础库版本 |
| `Failed to load font` 之类告警 | 本项目不依赖任何远程字体与 UI 库，不会出现 |
| `npm run seed --force` 提示「删除失败」 | 某些环境把 `fs.unlinkSync` 劫持为「移到回收站」且可能失败。脚本已容错，导入会正常完成，只是旧解析中间文件可能残留，不影响使用 |
| 改了 `CHUNK_SIZE` 但切片没变 | 切片在入库时生成。重新导入：`npm run seed --force`，或在知识库详情页对文档点「重新解析」 |
| 想让「XX 词」也能命中 | 往 `server/rag/synonyms.js` 的 `GROUPS` 加一组，重启引擎后跑 `npm run eval` 验证 |

## 十、已知限制

1. **PDF 只支持文本型**。扫描件（图片型 PDF）与 CID 字体子集无法还原，会明确报错。建议先用 OCR 转文本，再走「粘贴文本」入库。
2. **单用户本地部署**。没有账号与多租户，靠 `ACCESS_TOKEN` 做一层门禁。多人使用请部署多实例或自行加鉴权层。
3. **JSON 文件存储**。切片量在几千级别很轻快；上万条且要求高并发的场景应换成 SQLite/Postgres + 向量库（`store.js` 的接口已收敛，替换成本低）。
4. **解析是进程内异步任务**。重启引擎会中断正在进行的解析，重启后这些文档停留在「解析中」，点一下「重新解析」即可。
5. **助手「指定模型」只覆盖模型名**，不覆盖服务地址与密钥（那是服务端配置，不下发到客户端）。
